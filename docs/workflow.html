Path Filters — What triggers a rebuild?

The workflow only fires when a push to main touches at least one of these files:

File Why it triggers a rebuild
docker/Dockerfile The image recipe itself — any change here changes one or more layers.
docker/init-db.sh Baked into the image via COPY. Changes here affect the layer that seeds the database on first container run.
sql/pg.spi.foo.sql Fetched by init-db.sh at container startup from GitHub raw URL. Technically does not need an image rebuild (it's downloaded at runtime), but including it here ensures the published image is always tested against the latest SQL functions.
File changed Rebuild triggered?
docker/Dockerfile ✅ Yes
docker/init-db.sh ✅ Yes
sql/pg.spi.foo.sql ✅ Yes
docker/manage.sh ⏭️ No
README.md ⏭️ No
R/all_coor_ws.R ⏭️ No — R package is installed from GitHub at build time
.github/workflows/docker-publish.yml⏭️ No
💡 Note on R package updates Changing R source files under R/ does not trigger a rebuild because ws2pgdb is installed inside the container via remotes::install_github('rabravo/ws2pgdb') at build time. To pick up R changes you must push a change to docker/Dockerfile (even a comment bump) to force the last Docker layer to rebuild, or update the package in-place with docker exec -it pg-gis-plr R -e "remotes::install_github('rabravo/ws2pgdb')".
