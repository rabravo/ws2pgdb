Summary — What breaks and why

Failure Trigger Visible? Fix
Image and GitHub source out of sync Manual docker push before git push No — silent Always commit first
Container loads stale SQL functions init-db.sh fetches pg.spi.foo.sql from GitHub at startup; GitHub not updated yet No — wrong behavior, no error Commit pg.spi.foo.sql before pushing image
R package in image is stale remotes::install_github in Dockerfile pulls from GitHub; R changes not committed No — silent wrong results Commit R changes before triggering build
Two developers build different images GitHub has old code; Docker Hub has new image Yes — reproducibility broken GitHub commit is the single source of truth
GitHub Actions overwrites manual push Next push touching Dockerfile triggers Actions, rebuilds from GitHub state Yes — manual image lost Never push images manually
✅ The Golden Rule git commit → git push origin main → GitHub Actions builds → manage.sh option 10 pulls.
GitHub is the source of truth. Docker Hub is its compiled output. Never reverse that order.
⚠️ The sneakiest failure The init-db.sh SQL mismatch produces no error — the container starts cleanly, extensions load, but the PL/R functions running inside PostgreSQL are from the old version. You would only discover this by testing function behavior, not by reading logs.
